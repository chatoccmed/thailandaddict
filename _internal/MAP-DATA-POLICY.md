## 1. หลักการเดียวที่สำคัญที่สุด: **ไม่เดาพิกัด**

พินที่ผิดแย่กว่าไม่มีพิน

- ไม่มีพิกัด = หน้ารีวิวโชว์ **ที่อยู่เป็นลิงก์ค้นหาใน Google Maps** (ค้นหาด้วยชื่อ+ที่อยู่ ไม่ได้ปักหมุดอ้างว่าอยู่ตรงนี้)
- ไม่มีพิกัดพอ = **แผนที่ไม่ขึ้นเลย** (เกณฑ์ ≥60% ต่อชนิด และ ≥3 จุด) — ดีกว่าแผนที่ที่พินหาย 40%
- **ห้ามใช้จุดกลางจังหวัด/อำเภอ/ถนน หรือจุดกลางของพื้นที่ใหญ่ แทนตำแหน่งของสถานที่** ไม่ว่าในกรณีใด
- **"Nominatim ตอบว่าเจอ" ไม่ได้แปลว่าเจอตัวอาคาร** — ความละเอียดต้องมาจาก *สิ่งที่มันจับได้จริง* (category / type / place_rank ของ `format=jsonv2`) ไม่ใช่จากชนิดคำถามที่เราส่งไป · เคยบันทึกทุกคำตอบของคำถามชื่อ/ที่อยู่เป็น `poi` ทำให้พินโรงแรม 93 จุดคือถนนหรือหมู่บ้าน
- พินหน้ารีวิวคือ **ปลายทางนำทาง** (ลิงก์ที่อยู่เปิด Google Maps ที่ lat,lng) · พินในแผนที่บทความ/hub คือตำแหน่งบนแผนที่ (ลิงก์นำทางของ block ค้นหาด้วยชื่อ) → พินโรงแรมผิดทำให้คนเดินไปผิดที่จริง
- ในตัวแคช/สโตร์ เก็บ "หาไม่เจอ" ไว้พร้อมเหตุผล — นั่นคือกฎนี้ทำงาน ไม่ใช่งานที่ยังไม่เสร็จ

### กฎการจับคู่ของ `geocode-poi-overpass.mjs` (ทุกข้อมาจากผลที่วัดได้จริง)

1. **ชื่อตรงเป๊ะ ไม่ใช่มีคำร่วม** — "วัดม่วง" เหลือคำเดียวหลังตัดคำหมวด และกล่องอ่างทองมีทั้ง วัดม่วง / วัดม่วงเจริญผล / วัดม่วงหวาน / โรงเรียนวัดม่วงเจริญผล · มีแต่ชื่อตรงเป๊ะที่แยกได้
2. **ถามแบบ exact equality ไม่ใช่ regex** — `nwr["name"="X"]` ใช้ index · regex ไม่มี tag filter สแกนทั้งกล่อง กรุงเทพฯ ไม่เคยจบ
3. **เลือก node ก่อน polygon** — node คือจุดที่คนปักไว้ · polygon คืนจุดกลาง ซึ่งของอุทยานคือกลางป่า 9 กม.
4. **ปฏิเสธ polygon พื้นที่ใหญ่** — `natural=water` (อ่างเก็บน้ำเขื่อนอุบลรัตน์ = กลางน้ำ ~400 ตร.กม.), `boundary=national_park` ฯลฯ · ยกเว้นสิ่งที่ตัวมันคือจุดเที่ยวเอง (สระมรกต `tourism=attraction`) และเกาะ · ตรวจย้อนหลังวัดขนาดด้วย: มุมถึงจุดกลาง >400 ม. = ใหญ่ (บึงพลาญชัย 327 ม. จึงคงไว้)
5. **ชนิดต้องตรง** — block ที่เป็นร้านอาหาร (มี cuisine/signature/mustOrder) ต้องจับคู่กับสิ่งที่ขายอาหาร · "Baan Tepa" ร้าน 2 ดาวมิชลินที่บางกะปิ เคยไปแมตช์เกสต์เฮาส์ชื่อเดียวกันห่าง 17 กม.
6. **คลุมเครือที่ 400 ม.** — วัดจาก 112 กลุ่มชื่อซ้ำ: 0–200 ม. = ที่เดียวกัน map สองรอบ · >2 กม. = คนละที่ (วัดม่วง 2 แห่งห่าง 45.7 กม.)
7. **ต้องอยู่ใกล้พินพี่น้องในบทความเดียวกัน (เฉพาะย่าน กทม./เกาะ)** — กล่องของย่านคือทั้งกรุงเทพฯ ทำให้สาขาชื่อเดียวกันที่อื่นแมตช์ได้ (Sunny Bear ห่างรายการบางเขน 14.1 กม.) · เกณฑ์ `max(3.5 กม., 1.5 × p90 ของบทความนั้น)` · **จังหวัดได้รับยกเว้น** เพราะทดสอบย้อนหลังแล้วทั้ง 3 จุดที่ถูกฟ้องเป็นของจริงไกลตัวเมือง (บทความเขียนเองว่า "ห่างตัวเมืองราว 45 กม.")
8. **ห้ามจับคู่กับ h1** — h1 คือพาดหัวขาย: "Ananya Lipe Resort" เคยไปแมตช์ "Walking Street Hostel"
9. **รายการ "A + B + C (D)" ใช้ชื่อได้แค่ชิ้นแรก** — วงเล็บหลัง "+" เป็นของชิ้นสุดท้าย: "แพ็กเกจเต็มวัน วัดร่องขุ่น + วัดร่องเสือเต้น + บ้านดำ + ไร่บุญรอด (สิงห์ปาร์ค)" เคยไปปักที่สิงห์ปาร์ค · "+" ในวงเล็บ ("บัตรโชว์ + บุฟเฟต์") ไม่นับเป็นรายการ
10. **จุดกลางของ polygon ต้องอยู่บนตัวมันเอง** — `out center` คือจุดกลาง*กรอบสี่เหลี่ยม*: เกาะเสม็ดเคยลอยกลางทะเล 287 ม. · หาดทุ่งวัวแล่นห่างหาด 181 ม. · ทุก polygon ที่ผ่านจะถูกดึง geometry มาตรวจ — อยู่นอกโครงร่าง >50 ม. ย้ายไปจุดบนตัวมันที่ใกล้จุดเดิมที่สุด (บนช่วงกว้าง ≥ max(20 ม., 10% ของช่วงกว้างสุด) กันตกขอบ) · ดึง geometry ไม่ได้ = ปฏิเสธ ไม่ใช่เชื่อไปก่อน · แคชที่ `_internal/.overpass-poi-geom-cache.json`
11. **พินที่ถูกลบด้วยหลักฐานแล้ว จะไม่กลับมาจาก OSM element เดิม** — อ่าน `_internal/pin-fixes.json` ก่อนยอมรับ

**Overpass: ทำทีละงานเท่านั้น** · หมุน mirror `maps.mail.ru` → `overpass-api.de` → `kumi.systems` · **ห้ามใช้ `overpass.osm.ch`** (มีแต่ข้อมูลสวิตเซอร์แลนด์ ตอบทุกคำถามของไทยว่า 0 ผลลัพธ์ ดูเหมือน "ไม่มีใน OSM") · คลัสเตอร์ที่ request ล้มเหลว **ห้าม cache เป็นว่าง** (เคยหาย 72 จังหวัดในรอบเดียว เพราะรันงานที่สองซ้อน) · Nominatim (คนละบริการ) 1 req/s และทีละงานเช่นกัน

## 3. สิ่งที่ `check-coords.mjs` ปฏิเสธ

1. **0 / null island** — 0,0 คือหน้าตาของการ parse ล้มเหลว แต่เป็น float คู่ที่ดูถูกต้อง
2. **นอกประเทศไทย** — lat 5.55–20.55, lng 97.30–105.70 · ทะเลอ่าวไทยจับได้ · **ยังจับไม่ได้: เวียงจันทน์** (18.0,102.6) เพราะห่างหนองคายแค่ 25 กม. จริงๆ — ต้องใช้ point-in-polygon ขอบประเทศ (OSM relation 2067731)
3. **สลับ lat/lng** — ในไทยประกาศตัวเอง (lat ≈ 100 เป็นไปไม่ได้) แต่รายงานแยกเพื่อให้แก้ง่าย
4. **เท่ากับ centroid จังหวัด** (≤25 ม.) — ไม่ใช่ "ใกล้" เพราะเมืองเก่าคือที่ที่โรงแรมจริงอยู่
5. **ผิดจังหวัด** — วัดจากจุดกลางจังหวัด 130 กม. ค่าเริ่มต้น + ตารางยกเว้นจังหวัดยาว · **33 ย่าน กทม. ผูกกับกรุงเทพฯ แล้ว** (เดิมไม่มี ร้านทองหล่อที่ปักผิดไปเชียงใหม่ 583 กม. เคยผ่าน gate ได้)
6. **twin drift** — พิกัดใน `reviews-en` / `-zh` / … ต้องเท่ากับต้นฉบับไทย
7. **artifact ค้าง** — `astro/src/data/review-coords.json` ต้องตรงกับเนื้อหา (คลาดได้ ≤2 ม.) → รัน `gen-feeds` หลังแก้พินทุกครั้ง
8. **ไกลจากทุกจังหวัด** — อยู่ในกรอบไทยแต่ห่างจุดกลางทุกจังหวัด >130 กม. · สำหรับบทความระดับประเทศ (`cluster:"thailand"`)
9. **สถานที่ต่างกันใช้พินเดียวกัน** — ครอบ**ทุกพิกัดในเนื้อหา** ทั้งรีวิวและ `blocks[]` (เดิมอ่านแค่รีวิวโรงแรม = 27% ของพิกัด) · เทียบชื่อหลายรูป รวมสลับไทย-อังกฤษ และ OSM id เดียวกัน = ตึกเดียวกัน
   - 19 กลุ่มที่เจอตอนขยายกฎ (ส่วนใหญ่คือคาเฟ่ที่ใช้พิกัดของห้างที่ตัวเองอยู่) **ลบแล้วตามที่เจ้าของอนุมัติ** · ratchet `shared-positions-baseline.json` **ว่างเปล่า** = กฎนี้ไม่มีข้อยกเว้นแล้ว
   - การลบพินชนกันทำได้ที่เดียว: `drop-shared-positions.mjs` ซึ่งอ่านคำตัดสินจาก gate (`--json`)
10. **พินระดับถนน/พื้นที่** (`road-level-pin`) — แถวใน `hotel-coords.json` ที่เป็น `precision:'road'` หรือ `'area'` ห้ามมีพินตรงจุดนั้นอยู่ในเนื้อหา · `drop-road-pins.mjs` ลบเฉพาะกลุ่มนี้ (เดิมมีตรรกะ "ชนกัน" ของตัวเองที่อ่อนกว่า gate — จะลบพิน Mayflower ที่ถูกต้อง 4 ไฟล์ ถ้ารัน)

เทียบกับ gate แบบที่เว็บอื่นใช้ (ปฏิเสธ 0 + ปฏิเสธ lat นอกช่วง = 2 ข้อ) อันนี้ครอบ 10 ข้อ และตรวจข้าม 9 ภาษา

## 4. ODbL — คำว่า "contributors" ไม่ใช่ของประดับ

สตริง attribution ที่ถูกต้อง **มีแบบเดียว**:

```
&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors
```

และถ้าใช้ tile ของ CARTO ต้องบวก:

```
&copy; <a href="https://carto.com/attributions">CARTO</a>
```

เคยพลาดแล้วจริง: `'&copy; OpenStreetMap'` หลุดไป **1,311 หน้า** เพราะสตริงเดียวถูกก๊อปไป 4 generator
ตอนนี้ `check-map-attribution.mjs` อ่านทั้ง **generator** และ **ผลลัพธ์**

> gate ตรวจแบบ "ไฟล์เดียวกัน" ถ้าวันหนึ่งย้ายโค้ดแผนที่ไป bundle แยก ต้องย้าย gate ตามไป **ไม่ใช่ผ่อนกฎ**

เนื้อหามีหลายรูปแบบ: บรรทัดเดียว (minified), เว้น 1, เว้น 2, และแบบผสม (`tags` อยู่บรรทัดเดียว, object เล็กอยู่บรรทัดเดียว)
`JSON.stringify(obj, null, 2)` เคยทำให้การลบพิกัด 2 ค่ากลายเป็น diff +548/−1

ทุกสคริปต์ที่เขียนเนื้อหาใช้ `_internal/lib/json-format.mjs` → **แก้เฉพาะบรรทัดที่เปลี่ยน** แล้วตรวจด้วยการ parse ซ้ำ
ถ้าแก้แบบนั้นไม่ได้ จึงค่อยเขียนทั้งไฟล์ในรูปแบบเดิมที่ตรงไบต์ต่อไบต์ · **ห้ามเขียน writer ใหม่ด้วย `JSON.stringify` ตรงๆ**

## 8. เครื่องมือ

```bash
node _internal/geocode-hotels.mjs --report                         # หาพิกัดโรงแรมที่ยังไม่มี (--attractions เลิกใช้แล้ว)
node _internal/geocode-overpass.mjs --report                       # อัปเกรดพินระดับถนน/พื้นที่ → ตัวอาคาร
node _internal/geocode-poi-overpass.mjs --report                   # ร้านอาหาร/สถานที่ใน blocks
node _internal/geocode-poi-overpass.mjs --attractions --report     # ที่เที่ยว
node _internal/geocode-poi-overpass.mjs --report --offline --out x.json   # จับคู่ใหม่จาก cache ไม่แตะเน็ต + รายการเต็ม
node _internal/fix-pins.mjs [--batch <id>]                         # ลบ/ย้ายพินตามหลักฐานใน pin-fixes.json (dry run)
node _internal/drop-road-pins.mjs                                  # ลบพินระดับถนน/พื้นที่ (dry run)
node _internal/drop-shared-positions.mjs                           # ลบพินที่สถานที่ต่างกันใช้ร่วมกัน (dry run)
node _internal/qa/audit-transit-claims.mjs                         # ตรวจคำอ้างเดินถึง BTS (และจับพินผิด)
node _internal/gen-feeds.mjs                                       # สร้าง review-coords.json ใหม่
node _internal/qa/check-coords.mjs [--list|--json]                 # gate
node _internal/qa/check-map-attribution.mjs                        # gate
```

ลำดับที่ถูก: geocode (`--report` → ตรวจรายการ `--out` → `--apply`) → `gen-feeds` → `check-coords` → `gen-hubs`

## 9. แก้พินด้วยหลักฐานภายนอก · `fix-pins.mjs`

gate ตัดสินได้เฉพาะสิ่งที่ดูจากข้อมูลเราเองออก (ถนน, ชนกัน, นอกไทย) · พินผิดบางแบบต้องใช้หลักฐานจากข้างนอก —
geometry ของ OSM, ลำดับเลขที่บ้าน, สิ่งที่ Nominatim จับได้จริง — จึงบันทึกเป็นรายการใน `_internal/pin-fixes.json`
หนึ่งรายการต่อหนึ่งพิน: `batch · action (drop|move) · kind (articles|reviews|place-coords) · slug · at · pos · to · osm · rule · evidence`

- แก้ครบ 9 ภาษา เฉพาะไฟล์ที่พินยังตรงจุดเดิม (twin ที่ blocks ไม่ตรงกันจะไม่ถูกแตะ)
- สโตร์: `place-coords` → miss record `{why, q}` · `hotel-coords` → คงจุดไว้แต่ `precision:'road'|'area'` + `why` (ให้ `geocode-overpass` หาอาคารจริงต่อได้) · move → จุดใหม่ + เก็บจุดเก่าไว้ที่ `was`
- `geocode-poi-overpass` อ่านไฟล์นี้ (กฎข้อ 11) · `geocode-hotels` ไม่เขียนแถวที่ไม่ใช่ `poi`
