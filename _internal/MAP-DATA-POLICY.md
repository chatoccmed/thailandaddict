กฎทั้งหมดในเอกสารนี้มีสคริปต์บังคับอยู่จริง ถ้าแก้กฎ ต้องแก้สคริปต์ด้วย
ไม่ใช่แก้เอกสารอย่างเดียว:

| กฎ | สคริปต์ที่บังคับ | exit |
|---|---|---|
| พิกัดทุกจุดต้องเป็นสถานที่จริงในไทย | `_internal/qa/check-coords.mjs` | 11 |

| แผนที่จะขึ้นเฉพาะเมื่อมีพิกัด ≥60% | ตัวเลย์เอาต์เอง (RoundupLayout / gen-hubs) | — |

## 1. หลักการเดียวที่สำคัญที่สุด: **ไม่เดาพิกัด**

พินที่ผิดแย่กว่าไม่มีพิน

- ไม่มีพิกัด = หน้ารีวิวโชว์ **ที่อยู่เป็นลิงก์ Google Maps** (พฤติกรรมนี้มีมาตั้งแต่ 2026-07-18)
- ไม่มีพิกัดพอ = **แผนที่ไม่ขึ้นเลย** (เกณฑ์ ≥60% ต่อชนิด และ ≥3 จุด) — ดีกว่าแผนที่ที่พินหาย 40%
- **ห้ามใช้จุดศูนย์กลางจังหวัด/อำเภอ/ถนน แทนตำแหน่งของสถานที่** ไม่ว่าในกรณีใด

ปัจจุบัน **1,552 รายการถูกบันทึกว่า "หาไม่เจอ" และไม่มีพิกัด** — นั่นคือกฎนี้
ทำงาน ไม่ใช่งานที่ยังไม่เสร็จ

## 2. ที่มาของพิกัด (source of truth ต่อชนิด)

| ชนิด | แหล่ง | ความแม่นยำ | เก็บที่ |
|---|---|---|---|
| ที่พัก | Nominatim (ชื่อโรงแรม → POI) | building | `_internal/hotel-coords.json` `precision:'poi'` |
| ที่พัก (อัปเกรด) | Overpass ในกรอบ bbox + จับคู่ชื่อ **2 คำขึ้นไป** | building | `via:'overpass'` + เก็บ OSM element id ไว้ตรวจย้อนหลังได้ |
| ที่พัก (ตกชั้น) | Nominatim เจอแต่ "ถนน" | **ถนน — ห้ามเป็นพิน** | `precision:'road'` เก็บไว้ในสโตร์ แต่ไม่เขียนลงเนื้อหา |
| ที่เที่ยว / ที่กิน | Nominatim (ชื่อ + จังหวัด) | POI | `_internal/place-coords.json` |
| จังหวัด | จุดกลางเมืองจังหวัด | **เป็น centroid โดยเจตนา** | `_internal/province-coords.json` — ใช้เป็นตัววัดระยะเท่านั้น |

ไม่มี Google Maps Platform ในสาย build: ไม่มี API key ให้รั่ว ไม่มีค่าใช้จ่าย และ
ToS ของ Google ห้ามเก็บ lat/lng ถาวรอยู่แล้ว (เก็บได้แค่ `place_id`)

## 3. เก้าข้อที่ `check-coords.mjs` ปฏิเสธ

1. **0 / null island** — 0,0 คือหน้าตาของการ parse ล้มเหลว แต่เป็น float คู่ที่ดูถูกต้อง
2. **นอกประเทศไทย** — lat 5.55–20.55, lng 97.30–105.70 · ทะเลอ่าวไทยจับได้ (อยู่ในกรอบ แต่ไกลจากทุกจังหวัด >130 กม.) · **ยังจับไม่ได้: เวียงจันทน์** (18.0,102.6) เพราะอยู่ห่างหนองคายแค่ 25 กม. จริงๆ — ต้องใช้ point-in-polygon ขอบประเทศ (OSM relation 2067731) ถึงจะปิดช่องนี้
3. **สลับ lat/lng** — ในไทยประกาศตัวเอง (lat ≈ 100 เป็นไปไม่ได้) แต่รายงานแยกเพื่อให้แก้ง่าย
4. **เท่ากับ centroid จังหวัด** (≤25 ม.) — ไม่ใช่ "ใกล้" เพราะเมืองเก่าคือที่ที่โรงแรมจริงอยู่
5. **ผิดจังหวัด** — วัดจากจุดกลางจังหวัด 130 กม. ค่าเริ่มต้น มีตารางยกเว้นสำหรับจังหวัดที่ยาวจริง (กาญจนบุรี 190, ประจวบ 180, เชียงใหม่ 200 …)
6. **twin drift** — พิกัดใน `reviews-en` / `-zh` / … ต้องเท่ากับต้นฉบับไทย
7. **artifact ค้าง** — `astro/src/data/review-coords.json` ต้องตรงกับเนื้อหา (คลาดได้ ≤2 ม.)
8. **ไกลจากทุกจังหวัด** — อยู่ในกรอบไทยแต่ห่างจุดกลางทุกจังหวัด >130 กม. (เช่น กลางอ่าวไทย) · ใช้กับบทความระดับประเทศ (`cluster:"thailand"` 2,372 พิกัด) ที่ไม่มีจังหวัดให้เทียบ
9. **พินซ้ำตำแหน่ง** — โรงแรม**ต่างชื่อ** ≥2 แห่งที่พิกัดเดียวกัน 5 ตำแหน่งทศนิยม = คำตอบนั้นคือพื้นที่ ไม่ใช่ตัวอาคาร (โรงแรมเดียวที่มีหลาย slug ไม่นับ — อาคารเดียวกันจริง)

เทียบกับ gate แบบที่เว็บอื่นใช้ (ปฏิเสธ 0 + ปฏิเสธ lat นอกช่วง = 2 ข้อ)
อันนี้ครอบ 9 ข้อ และตรวจข้าม 9 ภาษาให้ด้วย (5,029 twin)

**กฎจับคู่ชื่อของ `geocode-overpass.mjs` — 2 คำขึ้นไป ไม่มีข้อยกเว้น**
ลองผ่อนสองรอบ ผิดทั้งสองรอบ:
- "คำยาว ≥6 ตัวอักษร" → รับ *Chateau de Sukhumvit ≈ Sukhumvit Suites* (สุขุมวิทคือถนน)
- "คำที่ไม่ซ้ำใครในพื้นที่" → รับ *Chateau de Sukhumvit ≈ Chateau de Bangkok*, *Hotel De Nara ≈ Nara Place*, *Yellow Pillow Village ≈ La Pillow*
  (การเป็น "chateau" เดียวใน OSM ไม่ได้ทำให้ chateau สองแห่งเป็นตึกเดียวกัน — ความไม่ซ้ำบอกแค่ว่า OSM เก็บข้อมูลไว้เท่าไร ไม่ได้บอกตัวตน)

และ **ห้ามจับคู่กับ h1** — h1 คือพาดหัวขาย ไม่ใช่ชื่อ: "Ananya Lipe Resort" ไปแมตช์ "Walking Street Hostel" เพราะ h1 เขียนว่า "เดินไม่กี่ก้าวก็ถึง Walking Street" · พาดหัวบอกว่า *ใกล้อะไร* ซึ่งตรงข้ามกับการบอกว่า *คือที่ไหน*

## 4. ODbL — คำว่า "contributors" ไม่ใช่ของประดับ

สตริง attribution ที่ถูกต้อง **มีแบบเดียว**:

```
&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors
```

และถ้าใช้ tile ของ CARTO ต้องบวก:

```
&copy; <a href="https://carto.com/attributions">CARTO</a>
```

เคยพลาดแล้วจริง: `'&copy; OpenStreetMap'` หลุดไป **1,311 หน้า** เพราะสตริงเดียว
ถูกก๊อปไป 4 generator แล้วไม่มีอะไรจับได้ ตอนนี้ `check-map-attribution.mjs`
อ่านทั้ง **generator** และ **ผลลัพธ์** — ถ้าไฟล์ไหนโหลด tile แต่ไม่มีคำว่า
"contributors" build ล้มทันที

> ข้อควรรู้: gate ตรวจแบบ "ไฟล์เดียวกัน" ถ้าวันหนึ่งย้ายโค้ดแผนที่ไป bundle แยก
> ต้องย้าย gate ตามไป **ไม่ใช่ผ่อนกฎ**

## 5. Leaflet self-host ทั้งหมด

`astro/public/js/leaflet-1.9.4.js` + `astro/public/css/leaflet-1.9.4.css`
ยืนยัน SHA-256 ตรงกับ SRI hash ของ unpkg ที่เคยใช้ → ไบต์เดียวกัน แต่ออกจาก
origin ของเราเอง ไม่มี third party ที่เปลี่ยนโค้ดที่รันบนหน้าเว็บได้

⚠️ แผนที่ทุกตัวใช้ `L.divIcon` — ไม่ได้พึ่งรูป marker เริ่มต้นของ Leaflet
(`/css/images/marker-icon.png` ไม่มีในเว็บ) ถ้าจะเพิ่ม `L.marker` แบบไม่ใส่ icon
ต้องเอาโฟลเดอร์ `images/` ของ Leaflet มาด้วย — และนั่นกิน 6 ไฟล์จากเพดาน
Cloudflare 20,000 ไฟล์ที่เหลือที่ว่างอยู่ไม่มาก

## 6. เครื่องมือ

```bash
node _internal/geocode-hotels.mjs --report        # หาพิกัดโรงแรมที่ยังไม่มี
node _internal/geocode-hotels.mjs --attractions   # โหมดที่เที่ยว
node _internal/geocode-overpass.mjs --report      # อัปเกรดพินระดับถนน → ตัวอาคาร
node _internal/drop-road-pins.mjs                 # ลบพินที่ไม่ซื่อสัตย์ (dry run)
node _internal/gen-feeds.mjs                      # สร้าง review-coords.json ใหม่
node _internal/qa/check-coords.mjs --list         # gate
node _internal/qa/check-map-attribution.mjs       # gate
```

ลำดับที่ถูก: `geocode-overpass --apply` → `drop-road-pins --apply` → `gen-feeds` → `check-coords`
